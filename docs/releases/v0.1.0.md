# Release v0.1.0 — Prototype (HDL generation)

**Date:** 2026-07-07

The first public release establishes the research platform and its engineering
foundation.

## Implemented features
- Config-driven architecture: models, prompts, benchmarks, synthesis,
  verification and optimization are all structured YAML — no hard-coded logic.
- Model providers: deterministic `reference` (upper bound), `synthetic`
  (fidelity-parameterised controls) and real `anthropic` (cached for repro).
- Benchmark suite v1: 18 benchmarks across arithmetic, FSM, communication,
  memory, processor, DSP and control, each with structured metadata, an
  objective difficulty score and a verified reference implementation.
- Evaluation harness with an identical procedure for every model; toolchain
  stages (GHDL/Yosys) degrade gracefully when tools are absent.
- Experiment registry (SQLite) with full provenance; structured JSONL logs.
- Leaderboards with Wilson 95% confidence intervals; category and difficulty
  breakdowns; auto-generated JSON/CSV/Markdown/HTML reports and SVG figures.
- `reproduce.py` regenerates every figure, table, report, publication artifact
  and website page from the experiment registry.
- Engineering: 48 tests (unit/integration/regression/e2e), ~88% coverage, Ruff,
  mypy, pre-commit, Dockerfile, dev container, GitHub Actions CI, issue templates.

## Architectural changes
- Introduced the `hdleval` src-layout package with plugin registry, DAG
  orchestration, RAG retriever and self-repair diagnosis interfaces.

## Known limitations
- The public baseline uses reference/synthetic providers as controls; real-model
  numbers require an API key.
- Without GHDL/Yosys, compile/synth/sim are `skipped` and functional correctness
  uses a documented static fallback (full results via the Docker image).
- Difficulty weights are fixed a priori, not yet empirically calibrated.
